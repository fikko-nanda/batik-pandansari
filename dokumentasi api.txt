1. TUJUAN DAN CARA MEMBACA DOKUMEN
----------------------------------
Dokumen ini adalah rancangan endpoint REST API untuk backend e-commerce Batik Pandansari. Daftar disusun per modul agar dapat menjadi acuan implementasi Laravel, pengujian melalui Postman, dan integrasi frontend. Endpoint yang tercantum belum berarti seluruhnya sudah dibuat di aplikasi.
Prefix endpoint menggunakan /api.
GET membaca data; POST membuat data atau menjalankan aksi; PUT/PATCH memperbarui; DELETE menghapus atau menonaktifkan.
Parameter {id} merupakan placeholder untuk ID data terkait.
Akses 'Owner' berarti pengguna hanya boleh mengakses data miliknya sendiri; pemeriksaan harus dilakukan di backend.

3.1 Alur Lupa Password dengan OTP
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Catatan keamanan: OTP sebaiknya memiliki masa berlaku singkat (contoh 5 menit), dibatasi jumlah percobaan, disimpan dalam bentuk hash, dan hanya dapat digunakan sekali. Token reset harus acak, singkat masa berlakunya, dan terpisah dari token login. Password baru harus di-hash menggunakan mekanisme Laravel.

3.2 Implementasi API Autentikasi (Tahap 1 - SUDAH DIBUAT)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Status: POST /api/register, POST /api/login, POST /api/logout, dan GET /api/me
sudah dibuat dan diuji.

Catatan penting (disesuaikan dengan schema database aktual):
- Nilai peran (role) di tabel users adalah enum('pelanggan','admin'), bukan
  'customer'/'teknis' seperti pada rancangan awal. Registrasi publik HANYA
  membuat akun dengan peran 'pelanggan'; field peran pada request diabaikan.
- Autentikasi memakai token Laravel Sanctum (personal access token). Tabel
  personal_access_tokens dibuat manual dengan tokenable_id bertipe char(36)
  mengikuti id_user (UUID), dan tidak menjalankan migration default.
- Kirim header "Authorization: Bearer <token>" untuk /api/logout dan /api/me.

POST /api/register (publik) - body:
  nama_pengguna   (wajib, string, maks 100)
  email           (wajib, format email, unik, maks 150)
  nomor_telepon   (opsional, string, maks 20)
  kata_sandi      (wajib, min 8; wajib menyertakan kata_sandi_confirmation)
Respons 201: data pengguna tanpa token (login dilakukan terpisah).

POST /api/login (publik) - body: email, kata_sandi.
Respons 200: { token, token_type: "Bearer", user }. Gagal -> 401.

POST /api/logout (login) - menghapus token yang sedang aktif.
GET  /api/me (login) - mengembalikan profil pengguna yang sedang login.

Format respons umum: { "success": bool, "message": string, "data": ... }.
Respons galat validasi (422): { "success": false, "message": ..., "errors": {...} }.
Respons belum login (401): { "success": false, "message": "Tidak terautentikasi..." }.

Catatan keamanan: OTP reset password pada 3.1 BELUM diimplementasikan dan
dikerjakan pada tahap paling akhir.

3.3 Implementasi API Alamat Pengguna (Tahap 2 - SUDAH DIBUAT)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Status: GET/POST /api/addresses dan GET/PUT/DELETE /api/addresses/{id} sudah
dibuat dan diuji. Semua endpoint memerlukan login (auth:sanctum).

Model: App\Models\UserAddress. Catatan schema: nama kolom primary key yang
aktif adalah id_user_address (dokumen panduan menulis id_address, namun yang
dipakai adalah struktur database aktif id_user_address). Tidak ada migration
baru; tabel sudah tersedia.

Kepemilikan: setiap query dibatasi id_user milik token. Alamat yang bukan
milik pengguna yang login menghasilkan 404 (bukan 403) agar keberadaannya
tidak terungkap.

Field alamat (semua wajib kecuali alamat_utama):
  label_alamat    (maks 30),  nama_penerima (maks 100),
  nomor_telepon   (maks 20),  nama_provinsi (maks 60),
  nama_kota       (maks 60),  nama_kecamatan (maks 60),
  kode_pos        (maks 10),  alamat_lengkap (teks),
  alamat_utama    (opsional, boolean)

Aturan alamat utama: alamat pertama otomatis menjadi utama; bila sebuah alamat
di-set alamat_utama=true maka alamat lain milik pengguna yang sama di-set
false, sehingga hanya ada satu alamat utama per pengguna.

GET    /api/addresses          - daftar alamat sendiri (urut utama lalu terbaru).
POST   /api/addresses          - buat alamat; id_user_address = UUID, id_user = token.
GET    /api/addresses/{id}     - detail alamat sendiri ({id} = id_user_address).
PUT    /api/addresses/{id}     - perbarui alamat sendiri (parsial).
DELETE /api/addresses/{id}     - hapus alamat sendiri.

4.1 Implementasi API Produk (Tahap 3 - SUDAH DIBUAT)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Status: GET /api/products, GET /api/products/{id} (publik) dan POST
/api/products, PUT /api/products/{id}, DELETE /api/products/{id} (admin)
sudah dibuat dan diuji. Endpoint varian dan gambar sudah dibuat pada 4.2;
data varian dan gambar juga dikembalikan menyatu pada detail produk.

Model: App\Models\Product (dengan ProductVariant dan ProductImage untuk
relasi). Nilai status_produk yang valid: draft, aktif, nonaktif
(default 'draft' sesuai schema database).

GET /api/products (publik) - parameter query opsional:
  search    (mencari pada nama_produk dan deskripsi)
  category  (berisi id_category)
  page, per_page (default 10, maks 100)
Hanya produk berstatus 'aktif' yang ditampilkan. Respons menyertakan
"meta": current_page, per_page, total, last_page.

GET /api/products/{id} (publik) - {id} adalah id_product (UUID). Menampilkan
produk 'aktif' beserta category, variants, dan images. Jika tidak ada atau
tidak aktif -> 404.

POST /api/products (admin) - body:
  id_category    (wajib, harus ada di tabel categories)
  nama_produk    (wajib, string, maks 150)
  slug           (opsional, unik, maks 180; bila kosong dibuat otomatis
                  dari nama_produk)
  deskripsi      (opsional, string)
  status_produk  (opsional, salah satu draft/aktif/nonaktif, default draft)
Respons 201 berisi data produk.

PUT /api/products/{id} (admin) - bersifat parsial (semua field opsional).
Slug tetap diperiksa unik dengan mengecualikan produk itu sendiri.

DELETE /api/products/{id} (admin) - menonaktifkan produk (soft delete:
status_produk diubah menjadi 'nonaktif'). Penghapusan permanen tidak
dipilih karena produk yang memiliki varian terikat foreign key.

Hak akses tulis memakai middleware auth:sanctum + alias 'admin' (EnsureUserIsAdmin).
Tanpa token -> 401; login dengan peran 'pelanggan' -> 403. Format respons
mengikuti konvensi yang sama dengan API autentikasi.

4.2 Implementasi API Varian dan Gambar Produk (Tahap 3 - SUDAH DIBUAT)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Model: App\Models\ProductVariant dan App\Models\ProductImage. Tidak ada
migration baru. Endpoint baca publik; endpoint tulis hanya admin.

Catatan schema: sku varian UNIQUE (uq_variants_sku); harga decimal(12,2)
NOT NULL; stok integer >= 0 default 0; status_varian default 'aktif'.
product_variants direferensikan cart_items, inventory_movements, order_items,
dan stock_opnames dengan ON DELETE RESTRICT, sehingga DELETE varian memakai
soft delete (status_varian='nonaktif'). product_images tidak direferensikan
tabel lain sehingga dapat dihapus permanen (file fisik ikut dihapus).

VARIAN:
GET  /api/products/{id}/variants (publik) - {id} = id_product. Hanya produk
     'aktif' dan hanya varian berstatus 'aktif' yang ditampilkan. Selain itu 404.
POST /api/products/{id}/variants (admin) - body:
     sku             (wajib, unik, maks 100)
     nama_varian     (opsional, maks 100)
     warna           (opsional, maks 50)
     ukuran          (opsional, maks 30)
     harga           (wajib, numerik >= 0)
     stok            (opsional, integer >= 0, default 0)
     status_varian   (opsional, aktif/nonaktif, default aktif)
PUT  /api/variants/{id} (admin) - {id} = id_variant; parsial; sku unik
     dengan mengecualikan varian itu sendiri.
DELETE /api/variants/{id} (admin) - soft delete: status_varian='nonaktif'.

GAMBAR:
GET  /api/products/{id}/images (publik) - {id} = id_product. Hanya produk
     'aktif'. Urut is_primary desc lalu urutan asc. Tiap item menyertakan "url".
POST /api/products/{id}/images (admin) - multipart/form-data:
     gambar     (wajib, file gambar jpg/jpeg/png/webp, maks 2MB)
     alt_text   (opsional, maks 150)
     is_primary (opsional, boolean)
     urutan     (opsional, integer >= 0, default max+1)
     File disimpan di disk 'public' folder products/; kolom path_gambar berisi
     path relatif. Gambar pertama otomatis primary; bila is_primary=true,
     gambar lain produk di-set false.
DELETE /api/images/{id} (admin) - {id} = id_image; hapus baris + file fisik.

Catatan: agar file dapat diakses lewat URL publik, jalankan
`php artisan storage:link` (symlink public/storage -> storage/app/public).
